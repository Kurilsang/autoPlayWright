# SPEC：评审修复批次 P0（报告链路完整性 · 计数回退 · 产物脱敏）

**Status:** ready-for-agent

**来源：** code-review 双轴评审（Standards / Spec 轴）结论中的 P0 批次，共 6 项正确性与红线问题。

## Problem Statement

框架的证据链路存在缺口：本应留痕的失败会凭空消失，本应跳过的用例在报告里无迹可查，本应判失败的空壳用例会被刷绿。测试工程师在复盘时无法信任报告的完整性——「报告里没有」不等于「没有发生」。

同时，快照产物会把产品名、个人账号等敏感内容直接落盘甚至入库，触碰项目红线，而现有流程没有任何机制拦截。

## Solution

让报告链路做到「发生即留痕」：任何失败（包括准备阶段）都产生失败事件并写入报告，任何跳过都在报告中标注原因，空壳用例在收集期即被拒绝。计数探测与解析共用同一条候选回退链，消除完成信号的静默误判。所有快照产物落盘前统一脱敏为占位符，产物目录对 git 兜底不可见。

## User Stories

1. As a 测试工程师, I want prepare/导航阶段失败也产出失败事件与报告明细, so that 我不会在报告里看到凭空消失的 flow
2. As a 测试工程师, I want 失败事件同样携带截图与证据字段, so that 修复报告链路不破坏现有取证能力
3. As a CI 使用者, I want 每次运行的产物目录标识全局唯一, so that 并行 worker 或同秒重跑不会互相覆盖
4. As a 测试工程师, I want 平台/环境不匹配的 flow 以 skipped 状态写入报告并标注原因, so that 我能核对用例矩阵到底执行了什么
5. As a QA lead, I want run 汇总区分 passed/failed/skipped 三态, so that 报表统计不把「跳过」当「通过」
6. As a 框架维护者, I want 空步骤的 flow 不能被判 passed, so that 空壳用例不会刷绿
7. As a 框架维护者, I want 空步骤列表在 DSL 加载期即被拒绝, so that 问题在收集期暴露而不是运行期
8. As a 框架维护者, I want 软计数探测与硬解析走同一条候选回退链, so that 完成信号不会因主候选失效而静默误判
9. As a 排障者, I want 定位器解析失败时异常携带全部候选的失败明细, so that 我能直接看出哪个候选为什么没命中
10. As a 排障者, I want 未知定位器名抛定位器未找到而不是内部 KeyError, so that 错误指向定位器仓库而非实现细节
11. As a 产品安全负责人, I want 快照产物落盘前统一脱敏为占位符, so that 产品名/账号/内网信息不会进入仓库
12. As a 框架维护者, I want 脱敏映射可配置, so that 新增产品名/域名无需改代码
13. As a 框架维护者, I want 文本类快照产物对 git 兜底不可见, so that 脱敏管道漏网也不会误提交
14. As a 人工复核者, I want 脱敏后的快照保留结构、信号与状态字段, so that 快照的诊断价值不受影响
15. As an AFK agent, I want 每项修复都有可自动核对的验收点, so that 我能独立完成票并自证
16. As a 后续维护者, I want 事件/报告 schema 变更保持旧报告可渲染, so that 历史产物不会因升级而不可读

## Implementation Decisions

- **准备阶段纳入事件模型**：flow 的准备回调（导航）失败时，产生一条失败步骤事件（错误文本 + 失败截图 + 证据字段），flow 结果必被构建、报告器回调必被调用。不再让准备失败绕过事件流。
- **空步骤防御双层**：DSL 校验层要求步骤列表非空（非法用例收集期报错，沿用「非法 DSL 收集期报错」既有决策）；引擎运行层兜底——若仍收到空步骤列表，判 failed 并附明确错误信息。
- **flow 结果状态扩为三态**：passed / failed / skipped，新增跳过原因字段。平台矩阵或环境过滤不匹配的 flow 以 skipped 写入明细与 run 汇总，汇总统计分列三态。
- **run 目录标识唯一化**：保留时间戳可读性，叠加进程/随机熵后缀保证全局唯一；并发执行互不覆盖，同秒重跑不合并。汇总写入时按已有明细合并，不覆盖并行产物。
- **计数与解析同链**：软计数（预期缺席的探测）与硬解析共用同一条候选回退链与同一个未找到异常；未找到异常携带全部候选的逐条失败原因。
- **脱敏器为纯函数**：快照/产物文本落盘前统一过脱敏器，敏感模式（产品名、人名/账号、内网主机、产品文案标识）映射为约定占位符；映射表来自配置，可扩展。脱敏只替换敏感串，保留 JSON/HTML 结构、信号时间线、状态字段与截图引用。
- **通用模式兜底（实现阶段补充决策）**：除映射外自动掩码邮件/有点账号句柄 → `<user>`、http(s) 主机 → `<host>`（含公网主机——宁可过掩码不可漏掩码，路径保留保住复现线索）；映射按词边界、长键优先替换，避免 yaml 等词内子串误伤。
- **git 兜底**：产物目录的文本类快照（JSON/HTML）纳入忽略清单，与既有 PNG 忽略并列；脱敏器是第一道防线，忽略清单是第二道。
- **事件/报告 schema 向后兼容**：新增字段有默认值，既有字段语义不变；HTML 渲染器同步识别三态徽章与跳过原因。
- **既有取证能力不回退**：失败事件的证据（归因分类/复现/信号时间线/冻结截图/对话上下文）结构保持不变。

## Testing Decisions

- **好的测试只测外部行为**：给定 flow spec 与注入件（页面/仓库/注册表/准备回调/报告器），断言 flow 结果形状与落盘产物内容；不断言内部调用序列，不断言错误文案措辞（断言错误类型与结构化字段）。
- **主缝——引擎产物**（复用现有引擎夹具站集成测试手法）：
  - 准备回调抛错 → 产生失败事件且明细 JSON 存在于 run 目录；
  - 空步骤列表 → 加载期被拒；运行期兜底判 failed；
  - 平台/环境不匹配 → run 汇总含 skipped 记录与原因，三态统计正确；
  - 连续两次构建报告器 → 产物目录不重名；
  - 既有通过/失败/证据用例全绿（回归，不回退取证能力）。
- **辅缝——定位器层 FakePage 单测**（复用现有手搓 FakePage 手法）：
  - 主候选命中 0 次 → 软计数回退到下一候选；
  - 未知定位器名 → 抛定位器未找到；
  - 全候选未命中 → 异常携带逐候选失败明细。
- **脱敏纯函数**（复用现有 crawler 纯函数测试手法）：
  - 含产品名/账号/内网主机的文本 → 敏感串被占位符替换且结构不变；
  - 无敏感内容 → 原样返回；
  - 新增映射条目 → 无需改代码即生效。
- **插件接线**：一条夹具站集成用例核对 run 汇总（skip 留痕从插件层贯通到报告），不为此新开测试缝。
- **全量回归**：框架自测全绿，lint 通过。

## Out of Scope

- P1/P2 批次：日志体系、认证配置校验、裸 selector 收口、定位器优先级校验与可见性判据、judge 语义（skip vs planned）与断言类型文档对齐。
- 票 05 既有范围：xdist 并发与 worker 上限、429 退避重试、Playwright trace 留存。
- 票 04 既有范围：hook 逃生舱、断言类型扩展、flow 级变量替换。
- **git 历史清洗**（已提交敏感产物的改写/过滤）：属高风险运维决策，需人工拍板，本 spec 只处置当前产物与后续产物。
- agent 判定加固（内容哈希稳定判据、网络层第二通道、跑飞归因）：另行立项。
